### Fixed (continued 4)
- Code review of issue #12 found a BLOCKING leak: a genuine `run_census_sql` execution error's raw exception text (`str(exc)`, potentially carrying internal driver/host/query detail) flowed unchanged into `recovery_log`, then into `_build_recovery_failure_message`'s output — streamed to the client as a `TOKEN` event and persisted to session history verbatim, with no model mediation. A `SqlRejected` message is unaffected — it's our own gate's controlled vocabulary (`validate_sql` violations), not raw driver text, so it stays real either way.
