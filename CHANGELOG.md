### Added
- Add `src/agent.py` implementing `agent_turn` (issue #7, M2 tracer bullet): session replay → hand-written Sonnet tool loop (no agent framework, CLAUDE.md rule 14) with exactly the three tools → streamed, grounded answer. Deliberately excludes the guardrail (#11), bounded recovery loop (#12), and 50s watchdog (#14) — all M3; a hard 8-iteration cap guards the loop in the meantime as an infra safety net, distinct from the future business-rule `MAX_RECOVERY_RETRIES`. Langfuse trace is a documented no-op wiring point (`_trace_turn_stub`) for issue #18 to fill in. Session-store I/O (`get_session`/`append_message`) runs via `asyncio.to_thread`, same as tool execution — code review caught the first version calling both directly on the event loop, which would serialize concurrent `/api/chat` requests on blocking SQLite I/O. **Verified end-to-end against live Anthropic + Snowflake**, not just unit-mocked (LLM behavior is a golden-eval target per rule 19, and this issue's own exit criteria ask for DF-01 passing manually): "Population of Alameda County, California?" → resolved geo `06001`, found `search_census_variables`'s population hit, self-corrected through a Snowflake case-sensitivity error via the model's own tool-loop retry (no coded recovery needed) → grounded answer, 1,661,584, with the 5-year-estimate caveat stated; re-verified after the `to_thread` fix

- Add `src/us_states.py`: static USPS state name↔abbreviation reference data, shared by `src/snapshot.py` (build-time display-name construction) and `src/tools.py` (`resolve_geography` input normalization) — see D-012

Only `user`/`assistant` messages are ever persisted — enforced at the type level, since `ChatMessage.role` has no tool-call literal by design (PRD §6); a test confirms `ChatMessage(role="tool", ...)` itself raises `ValidationError` before it could reach the store. Insertion order preserved via SQLite autoincrement `id`, not timestamp, since same-microsecond appends within a turn would otherwise tie. Adds `SESSION_DB_PATH` to `.env.example` (optional, defaults to `data/sessions.sqlite3`)
- Add `src/tools.py` implementing the agent's three tools (issues #3/#4/#5, CLAUDE.md rule 4). TDD, 22 tests written first, seeded through the real `build_snapshot` pipeline against a fake Snowflake connection rather than hand-mocked query results. `search_census_variables`: FTS5 over the local snapshot only, token-AND query construction (matches the validated retrieval strategy from the FTS-viability probe, docs/schema-notes.md Appendix A — not OR, which would rank a single-rare-term match above the true multi-term hit), `bm25()` negated so `VariableHit.score` is higher-is-better per contract, `geo_levels` set per D-009/C-3 (median variables → `[BLOCK_GROUP]` only, detected via a `"median" in label` heuristic — **flagged as unverified in D-011**, no live Snowflake connection was available to confirm against the real 28-table list). `resolve_geography`: exact case-insensitive match against the local geography table, `ambiguous=True` on 2+ candidates per D-002, deterministic `(state, geo_id)` sort independent of SQLite row order, `GeoCandidate.state` mapped to USPS postal abbreviation via a static 51-entry lookup. `run_census_sql`: `validate_sql` gate first (raises `SqlRejected`, never connects on rejection), `STATEMENT_TIMEOUT_IN_SECONDS` set via connector `session_parameters`, executes only the gate's sanitized SQL, never the raw input
- Add `src/snowflake_conn.py`, a shared key-pair-auth connection helper extracted from `src/snapshot.py` (which now imports it) to avoid a third near-duplicate copy of `scripts/sf_query.py`'s connection logic once `run_census_sql` needed the same credential path
- Add `src/snapshot.py` implementing `build_snapshot` (issue #2, CLAUDE.md rule 13): pulls ACS variable metadata and FIPS geography from Snowflake into local SQLite (FTS5 over variable label + ten breadcrumb columns) at startup, so runtime search never touches Snowflake. TDD, 15 tests written first. Guards two schema-notes.md traps: every `FIELD_LEVEL_*` breadcrumb column is `COALESCE`-wrapped before `CONCAT_WS` (unguarded, a NULL argument zeroes the whole indexed row), and the upstream-typo'd `"FIELD_LEVELl_9"` identifier is hardcoded verbatim. Geography table synthesizes state rows (deduped on `STATE_FIPS`) alongside native county rows, since the FIPS table carries no separate state-level grain. Writes build to a temp file and atomically renames onto the snapshot path, with a `snapshot_meta` completeness marker written last, so a crash mid-build can never leave a partial file for the next boot's no-op path to read (caught in review: the original version's no-op read had no error handling for exactly that case). - Add PRD §12 note that Cloudflare TLS termination can break Caddy's HTTP-01 challenge, requiring Full (strict) with an origin cert or a switch to DNS-01
- Add PRD §12 rationale for retaining basic auth (CLAUDE.md rule 18, no deviation): an unauthenticated endpoint calling Anthropic and Snowflake per request is an unbounded cost exposure, with credentials at the top of the README so reviewers are never blocked

### Changed
- Resolve all four `src/contracts.py` PROVISIONALs: `ALLOWED_TABLES` (31 tables, 2020 only), `GeoLevel` (5 members), `SENTINEL_CODES` (verified empty), `DEFAULT_VINTAGE` (2020)
- Remove `PLACE`, `CBSA`, `ZCTA` from `GeoLevel` — no place, CBSA, or ZCTA identifier exists anywhere in the 73 objects and there is no crosswalk to derive one
- Add `CensusValue.top_coded` and `TOP_CODES` (C-1): a Census top-code is a real value carrying special meaning, distinct from suppression, so it needed its own flag rather than being folded into `suppressed`
- Add `VariableHit.source` defaulting to `"acs"` (C-2), so nothing changes until the redistricting tables land at M3
- Reinterpret `VariableHit.geo_levels` as aggregation validity rather than availability (C-3), encoding the median-rollup trap as a data property tests can assert on instead of a prompt sentence the model may ignore
- Widen `normalize_value` with an optional `variable_id` for top-code lookup (non-breaking)
- Correct the metadata breadcrumb column name in schema-notes to `"FIELD_LEVELl_9"` (upstream typo, lowercase `l`)
- Reject star projection (`SELECT *`) at the SQL gate, mapped to the existing `SqlViolation.BANNED_CONSTRUCT` so `contracts.py` stays frozen — the B/C tables average ~280 columns and Snowflake is columnar, so `SELECT *` is a full-width scan that the injected `LIMIT 200` then turns into ~56,000 cells of model context; the row limit protects tokens and the projection rule protects scan cost, and bounding only one of them left the other open (D-007)
- Exclude `m`-suffixed margin-of-error rows from the FTS corpus, taking it from 8,164 to ~3,300 indexed rows, because estimate and MOE columns pair 1:1 with near-identical labels, so an indexed MOE row is a retrieval hit that reads like the answer — "median household income" could return `B19013m1`, a confidence-interval half-width, rendered as a dollar figure (D-008)
- Specify the geography snapshot as `2020_METADATA_CBG_FIPS_CODES` (~3.3K rows) explicitly, not `2020_METADATA_CBG_GEOGRAPHIC_DATA` (242,335 rows), because the phrase "geography index" admitted a 68×-larger reading that answers no question a user asks by name; the larger table stays allowlisted for Snowflake-side density queries but is never snapshotted
